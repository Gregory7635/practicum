# ADR-0003. Обработка сбоев: retries, резервный провайдер, безопасный fallback

- **Статус:** принято
- **Контекст:** внешний LLM может отвечать медленно, с ошибками или быть недоступным.
- **Решение (три уровня):**
  1. `OpenAiApiClient`: connect/read timeout (`AppConfig`) и повторные попытки (`llm.providers.openai.retries`).
  2. `AiGateway`: при сбое активного провайдера - переключение на `llm.fallback-provider` (если задан).
  3. Если недоступны все провайдеры - безопасный fallback-ответ; клиент получает HTTP 200 с пустым списком
     проблем и пояснением, а не 500.
- **Рассмотрено и отклонено:** полноценный circuit breaker (Resilience4j) - для учебного объёма избыточен;
  текущая реализация - failover без состояния: она не «размыкает цепь» после серии ошибок и каждый запрос
  заново пробует активного провайдера.
- **Последствия:** сервис устойчив к кратковременным сбоям. При реальной нагрузке стоит добавить circuit breaker,
  чтобы не ждать таймаут на каждом запросе к недоступному провайдеру.
